## Objective
Bind the agent's runtime identity and manage its credentials: a per-instance NPE identity bound to code+config+toolset+model (LG-IA-02), per-profile fail-closed credential isolation (LG-IA-03), managed-account inventory + managed secret source + authenticator lifecycle (LG-IA-01/04/05), and actor+subject+delegation claims into the ledger (LG-IA-10).

## What was built (all additive — no existing path renamed)
- **`agent/agent_identity.py`** (NEW, LG-IA-02) — `compute_instance_identity()`: `instance_id = sha256(code_hash · config_hash · toolset_hash · model_hash)`. `code_hash` covers the governance-surface source files; `config_hash` is the **redacted** canonical effective config (no secret embedded); `toolset_hash` is the sorted resolved tool/skill manifest; `model_hash` is `sha256(provider|model)`. Each input is fail-safe (`unknown:<name>` marker, never raises). Cached per (provider, model).
- **`agent/governance_audit_hooks.py`** — `_actor_for_agent` now returns the real computed identity, closing the `instance_id: None` stub P1.1/P1.2 carried. Every audit record's `actor` now binds the running code+config+toolset+model.
- **`lliam_cli/security_audit_startup.py`** (additive) — `emit_agent_identity_at_startup()` records a `config.load` / `agent.identity_bind` event carrying the identity; `_default_credentials_in_use()` (LG-IA-05) flags any credential-bearing env var set to a known default/placeholder (value never emitted, only the name), gated by `security.no_default_credentials`, wired into `run_security_audit`.
- **`gateway/run.py`** — additive call sites: emit identity + (existing) multiplex activation reads `gateway.multiplex_profiles`.
- **`docs/governance/agent_identity.yaml`** (NEW) — the LG-IA-02 binding record (inputs, algorithm, usage, review-by).
- **`cli-config.gov.yaml`** — `[ACTIVE @ P1.4]`: `identity.bind_instance`, `gateway.multiplex_profiles: true` (LG-IA-03 — activates the existing `secret_scope` fail-closed seam), `secrets.bitwarden` (LG-IA-04 config-of-record), `security.no_default_credentials` + `security.accounts` inventory (LG-IA-05/01), `delegation.max_spawn_depth` (LG-IA-10 config-of-record). **All under the single existing `security:` block** — a duplicate top-level `security:` key would silently drop the P0 posture (checked).

## Independent review + fixes (per-slice adversarial pass)
Both reviewers (logic + security) ran on this diff before push. No P1 blocker (the P0 posture, audit chain, and fail-closed gate are untouched; identity derivation is fail-safe and gates nothing). Both independently flagged the same three identity P2s — again the "tested green, inert in production" class — plus a credential-isolation P2; all fixed in-slice with regression tests:

- **P2 — startup identity was a phantom.** `emit_agent_identity_at_startup` ran with no agent and a raw (overlay-less) config → `model_hash = sha256("None|None")` and the FULL toolset (incl. `computer_use`/`browser` the CUI profile disables), so the flagship `identity_bind` record matched no operational actor. **Fixed:** it now resolves the merged config + the config-pruned toolset, so its `code_hash`/`config_hash`/`toolset_hash` MATCH the operational `tool.dispatch` actors (verified — differ only by the per-turn model, which is marked `resolved: per-turn` instead of a fake hash).
- **P2 — identity cache dropped the toolset/config inputs.** The cache keyed on `(provider, model)` only, so two same-model agents with different toolsets got a stale shared `instance_id` (and the differentiation tests all used `use_cache=False`, hiding it). **Fixed:** `toolset_hash` is memoized on the tool-registry generation (a swapped skill/MCP flips it), `config_hash` is recomputed each call, `code_hash` memoized once — a mid-process config/toolset change now yields a new id. Tests exercise the default cached path with two same-model/different-toolset agents.
- **P2 — code_hash coverage overclaimed "the controls' code".** It covered 7 files, missing the redaction boundary and policy gates. **Fixed:** expanded `_CODE_SURFACE` to include `agent/redact.py`, `agent/tool_guardrails.py`, `tools/tool_policy.py`, `tools/input_integrity.py`; the docstring + `agent_identity.yaml` now state honestly that code_hash is a change-signal over the governance CORE (whole-tree tamper-evidence is CI path-freeze + `file_safety` write-deny), deliberately excluding churny files.
- **P2 (security) — flipping `multiplex_profiles: true` without auditing the `_GLOBAL_ENV` allowlist.** `TERMINAL_SSH_*` (per-profile SSH command-exec credentials) matched the global `TERMINAL_` prefix → globally readable, a cross-profile leak vector under multiplex. **Fixed:** carved `TERMINAL_SSH_*` out of the global allowlist (the LG-IA-03 minimization the crosswalk requires) so they fail closed on an unscoped read; the 30+ legit `TERMINAL_` deployment settings stay global. **Note (LG-IA-03-R1, remediation pass):** `tools/terminal_tool.py` still reads these via `os.getenv` directly (bypassing `get_secret`) — migrating those call sites is required before any multi-profile deployment; the single-profile demo/eval boundary is unaffected.
- **P3s fixed:** removed the unread duplicate `secrets.no_default_credentials` key; broadened the default-credential name hints to cover AWS/bedrock (`ACCESS_KEY`/`AWS_`/`_KEY`) — a placeholder `AWS_ACCESS_KEY_ID` is now flagged.
