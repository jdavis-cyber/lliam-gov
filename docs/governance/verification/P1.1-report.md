## Expected-deny / expected-block cases
- Write failure on a `{mutating|privileged|egress|high_impact}` event → **blocked** (`AuditWriteError`, LG-AU-09).
- Corrupt/unreadable ledger tail → gated append **refused** (chain head unknown; appending would silently destroy tamper evidence).
- Agent file-tool write targeting `$LLIAM_HOME/logs/**` → **denied** (LG-AU-07).
- Unknown event type or decision value → **rejected** (`ValueError`, closed taxonomy).

## Capability preservation
Ledger is **off by default** (`ledger_enabled` absent/false in the shipped profile — low-side untouched); the gov overlay activates it. Logging is a write-only side channel; the only behavioral change is the intended LG-AU-09 fail-closed guarantee, scoped to consequential actions. `lliam_cli/dashboard_auth/audit.py` untouched — its never-block-auth semantics preserved. The `logs/` write-deny mirrors the existing unconditional `mcp-tokens`/`pairing` entries; no legitimate agent workflow writes there via file tools (system loggers write directly).
