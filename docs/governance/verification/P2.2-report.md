## Objective
Bind the PDP's hitl_approve tier to real, recorded human decisions: fail-closed
non-interactive handling (the R6 auto-approve gap), unconditional hardline
blocks, decision ledgering with approver identity, anti-fatigue tracking, JIT
risk rationale, and an appeal/override channel. NEW module
`tools/hitl_oversight.py` + additive edits in `tools/approval.py` and
`tools/tool_policy.py`.

## What was tested
1. **LG-HO-02 (the R6 gap closed):** strict posture + dangerous command +
   non-interactive/non-gateway context → **DENIED fail-closed** (was
   auto-approve-with-warning); the strict floor also beats
   `approvals.cron_mode: approve`. Low-side: shipped auto-approve preserved
   (capability).
2. **LG-HO-01/05/06:** high-risk proceeds WITH an approver (approval-backed
   JIT grant / interactive verdict), DENIED without one — fail-safe scoped to
   the High tier only (P2.1 PDP tests cover low/medium NOT gated — no fatigue).
3. **LG-HO-03:** sudo-stdin blocked even in an interactive session with
   approval state; hardline/deny remain terminal (no override re-enables —
   `operator_override` on a deny class raises).
4. **LG-HO-10/08:** the HO-02 denial, interactive prompt verdicts, JIT grants,
   and overrides each emit `approval.decision` to the hash-chained ledger with
   decision, approver identity, origin, and the concrete risk rationale
   (matched pattern description); denial messages tell the operator how to
   obtain approval.
5. **LG-HO-07:** approval prompts are counted per session; crossing the
   threshold (10) flags + logs an over-gating signal — prompts are never
   auto-approved by the limiter.
6. **LG-HO-09:** `operator_override(class, approver, justification)` = the
   appeal channel — approval-backed TTL grant, recorded with justification;
   requires an authenticated approver and a justification.
7. **LG-HO-04:** memory/skill staged write-approval confirmed active since
   P0.2 (`memory.write_approval`/`skills.write_approval: true` in the overlay);
   PDP classes `memory_write`/`skill_write` delegate to that backend (P2.1).
