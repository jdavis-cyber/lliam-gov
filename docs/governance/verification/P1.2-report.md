## Objective
Make the tool-dispatch path the single audit-generation chokepoint so every registered tool / skill / MCP invocation emits a governance-ledger record (LG-AU-02), fold the dashboard-auth stream + operator subject into the unified record (LG-AU-10), and stamp write-origin/provenance + model/provider traceability (LG-MC-03, LG-QT-03).

## What was built (all additive — no dispatcher renamed)
- **NEW `agent/governance_audit_hooks.py`** — the glue module: `predispatch_gate()` (emits `tool.dispatch`, returns a blocking `ToolGuardrailDecision` on a high-risk audit-write failure — LG-AU-09 at the seam), `record_outcome()` (terminal `tool.result` / `policy.violation`), `forward_auth_event()` (dashboard-auth bridge), `classify_risk()` (tool→risk-scope map), and `set_operator_subject()` (LG-AU-10 principal contextvar).
- **`agent/tool_executor.py`** — both dispatch paths (`execute_tool_calls_sequential` and `execute_tool_calls_concurrent`) call `predispatch_gate` after the existing plugin/guardrail block evaluation; a returned block flows through the existing guardrail-block path (same synthesized-result + post-hook behavior).
- **`model_tools._emit_post_tool_call_hook`** — the universal terminal-outcome funnel (both paths, inline dispatch and `handle_function_call`, all of success/error/blocked/cancelled) calls `record_outcome`, independent of and before the plugin observer gate.
- **`lliam_cli/dashboard_auth/audit.py` `audit_log()`** — additive forward into the chained ledger; the auth-log write is unchanged and the never-block-auth contract is preserved (the forward can never raise).
- **`cli-config.gov.yaml`** — `[ACTIVE @ P1.2]` keys (`chokepoint_required`, `on_unrecorded`, `unify_dashboard_auth`, `unify_acp`).

## What was tested

## Expected-deny / expected-block cases
- High-risk tool dispatch during an audit-write outage → **blocked** at the gate (fail-closed, LG-AU-09), surfaced as a guardrail-style block with a synthesized tool result.
- Already-blocked calls (plugin/guardrail/out-of-scope) → the gate is not consulted (they never execute); their block is still recorded downstream by `record_outcome` as `policy.violation`.

## Capability preservation
Every hook no-ops cheaply when the ledger is disabled (the shipped/low-side profile). The only behavioral change is the intended LG-AU-09 block, scoped to high-risk tools during an audit-write failure — read-only tools are never gated (bounded-availability trade). No tool/skill/MCP is removed or restricted; the dispatcher, `handle_function_call`, and `audit_log` are unchanged in behavior.
