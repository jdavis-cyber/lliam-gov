## What was tested
1. **LG-MC-02 (the key VERIFY — session isolation):** per-session/identity
   partition paths differ; an entry from `sess-A` is visible to `sess-A` but
   **not to `sess-B`**; a `shared`-scope entry is visible across sessions of
   the same identity; **cross-identity is never visible** even at shared scope.
2. **LG-MC-04:** a `critical`/`identity`/`policy`/`cross_session` write →
   requires HITL; a `routine` write → does not.
3. **LG-MC-05:** a TTL sweep purges entries older than the TTL and keeps
   recent ones (deterministic injected clock); PII content (`SSN …`) is
   flagged for exclusion from persistence; clean content is not.
4. **LG-MC-06:** `secure_purge` overwrites then unlinks a file and removes a
   partition tree; a missing path is a safe no-op.
5. **LG-MC-07:** `reset_session_context` securely purges a session's partition
   (working note gone) without touching the shared store.
6. **Capability preservation:** low-side posture → partitioning collapses to
   the shared store, nothing is swept/excluded, no write is gated (complete
   no-op).

## Expected-deny / expected-gate cases (by design)
- Session B reading session A's non-shared memory → **not visible** (MC-02).
- Cross-identity read of a shared entry → **not visible** (MC-02).
- Critical / identity / policy / cross-session memory write → **HITL** (MC-04).
- PII-tagged content → **excluded** from persistence (MC-05).
- Expired entries → **purged** on sweep (MC-05); partition securely wiped on
  task reset (MC-06/07).

## Notes
- `reset_session_context` refuses to purge when the partition collapses to the
  shared base (low-side guard) — a reset never nukes the shared store.
- Runtime wiring of `partition_path`/`entry_visible` into the memory provider's
  read/write path is a thin adapter deferred to the Phase 6 cutover adapter
  (the governance primitives + policy are proven here; the provider seam is
  `agent/memory_provider.py initialize(session_id, hermes_home=...)`).
