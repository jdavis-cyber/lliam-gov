## What was tested
1. **LG-MP-05:** a carded model → CUI-eligible; an uncarded model → **refused
   for CUI**; low-side → always eligible (no-op). Startup gate blocks a
   configured primary model with no card.
2. **LG-MP-07:** safetensors / gguf → **allowed**; the `.pt` / `.bin` /
   code-executing legacy formats → **denied**; a `.pt` with the `weights_only`
   safeguard → allowed; unknown suffix → deny-by-default; low-side → any format
   allowed (no-op).
3. **LG-MP-06:** a valid HMAC-signed manifest → verifies; a **tampered**
   manifest (field changed after signing) → invalid; an **untrusted signer** →
   invalid; a high-impact action with a runtime/manifest **mismatch** → blocked
   (`ToolGuardrailDecision.should_halt`); a match → proceeds; low-side → never
   blocks. Startup gate blocks a tampered manifest.
4. **Fail-closed provisioning:** missing manifests, missing signed primary,
   configured/signed model mismatch, unresolved signer placeholders, and
   attestation-module import failure all block strict startup.
5. **Runtime binding:** explicit runtime model switches must be carded and match
   a signed manifest model entry before the resolved client is returned.

## Design — enforcement seam
The fail-closed startup gate verifies the manifest, signer provisioning, signed
primary binding, and model card. Explicit runtime model selection repeats the
card + signed-manifest membership check. `attest_high_impact` remains an
additional guardrail helper for Phase 6 tool-level cutover; it is not claimed
as a live tool-dispatch boundary in this phase.

## Expected-deny cases (by design)
- Uncarded model for CUI; tampered / untrusted-signer manifest; high-impact
  action whose runtime model ≠ the signed manifest; code-executing model
  serialization formats without the `weights_only` safeguard.
