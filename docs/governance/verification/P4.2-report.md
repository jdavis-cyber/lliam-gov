## What was tested (the AI-494 VERIFY criteria)
1. **SoA lists all 188 controls with applicability + status:** parsed from
   `SoA.md` — exactly 188 rows, each with a valid status word; catalog has 188
   unique ids across 21 domains (130 Implemented · 1 Partially Implemented ·
   57 Planned). `soa_gate.py` reconciles SoA ↔ catalog ↔ poam and fails on a
   missing control, a status mismatch, a pending control without a poam_ref,
   or a dangling poam_ref (synthetic negatives exercised).
2. **godmode excluded with justification:** the SoA's excluded-sub-capabilities
   section records godmode/obliteratus as **never waivable** with the
   enforcement chain (skills.disabled + deny_tags + CI gate + waiver gate);
   CI-asserted by `soa_gate.py`.
3. **The tiering matrix IS the P2.1 PDP's:** `tool-risk-policy.yaml`
   `metadata.pdp_module == tools/tool_policy.py`; the PDP source loads that
   filename; every risk doc cites `policy/tool-risk-policy.yaml` and none
   cites the retired `capability_risk_policy.yaml` name; every determination's
   `action_classes` entry must exist in the matrix (verified).
4. **High-impact determination has a signature block:** each HID row carries
   `signed_acceptance {signed_by, role, date}` and
   `independent_reviewer {principal, disposition, date}` — placeholder values
   (PENDING/REPLACE/${VAR}/"[name]") are rejected by the test.
5. **POA&M discipline:** every `partial`/`planned` catalog control and every
   `partial` regulatory obligation resolves to a poam item with owner_role,
   scheduled_step, and milestone.
6. **Threat register:** all six mandatory classes covered; every cited control
   id exists in the catalog; every row carries owner/inherent/residual/status.
